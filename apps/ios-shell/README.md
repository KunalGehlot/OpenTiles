# apps/ios-shell — the iPad app

A [Capacitor](https://capacitorjs.com) 8 wrapper that ships the unchanged web app (`apps/web`) as a
free App Store app, plus one native addition: **MIDI keyboards through CoreMIDI**. No iOS or iPadOS
browser has Web MIDI (spec §5), so this app is the only way to practise with a MIDI keyboard on an
iPad. Everything else (microphone, on-screen keys, library, catalogue) is the web app as it is.
PLAN.md task **P3-01**.

> **Status: released for self-signing (v0.1.0, 2026-10-22).** Written on Linux; first built on macOS
> with Xcode 27 on 2026-10-09 (`xcodebuild -scheme App -destination 'generic/platform=iOS'`, no errors). Since
> 2026-10-22 it builds as an unsigned IPA that anyone can sign and install themselves
> ([Install it yourself](#install-it-yourself), ADR 0023). First installed on an iPad Pro (M1,
> iPadOS 27) with `pnpm device` on 2026-10-22 and played with a USB digital piano; the plugin tests
> run in CI on an iPad simulator. Work through the [first-build checklist](#first-build-checklist).

## How it works

1. **Detection.** Capacitor's native bridge defines `window.Capacitor` before any page script runs.
   `isNativeShell()` (`apps/web/src/lib/native-shell.ts`) checks it without importing Capacitor, so
   browsers never load Capacitor code: the plugin module is a separate, lazily imported chunk.
2. **Choosing the input.** `createMidiInput()` in `apps/web/src/input/midi-input.ts` returns
   `NativeMidiInput` inside the app and the Web MIDI `MidiInput` everywhere else. The practice
   screen's "Connect MIDI keyboard" button works the same in both. Inside the app the Library's
   "Add to Home Screen" hint is hidden, because there is no Home Screen step.
3. **The plugin.** One CoreMIDI client and one input port that asks for the MIDI 1.0 protocol.
   It connects to every online source on `start()` and to each source that appears later (setup
   notifications), decodes note-on and note-off (note-on with velocity 0 counts as note-off), and
   emits `noteOn` / `noteOff` with `{ pitch, velocity, channel, time }` and `devicesChanged` with
   `{ sources }`. The JavaScript API is in `plugins/core-midi/src/definitions.ts`.
4. **Timing.** CoreMIDI stamps each message with the host clock (`mach_absolute_time()`) when it
   arrives; the plugin converts that to seconds. `NativeMidiInput` lines that clock up with
   `performance.now()` through `getTime()` round trips, NTP style (three when starting, then one
   every 5 s; the shortest round trip of the last eight wins). Each note is then placed on the
   audio clock exactly as Web MIDI notes are: audio "now" minus the note's age. A busy main thread
   or a slow bridge therefore does not make a note look late.
5. **MIDI out** (P6-12). An output port sends the app's notes (Listen, the other hand, the Player)
   to a keyboard: `listDestinations`, `destinationsChanged`, `send({ destination, messages })` with
   each message's time in host seconds (CoreMIDI sends it when due, as MIDI 1.0 packets) and
   `flush` to drop what is still waiting. `NativeMidiInput.output()` is the web side: it maps
   `performance.now()` stamps onto host time with the same clock estimate and batches one bridge
   call per scheduling tick.
6. **Bluetooth MIDI.** Settings → MIDI keyboard → "Pair a Bluetooth MIDI keyboard" shows Apple's
   pairing screen (`CABTMIDICentralViewController`); a paired keyboard is then a source and a
   destination like a USB one. The iPad's own Bluetooth settings do not pair MIDI keyboards.
7. **Screen.** `keepAwake` keeps the screen on while the Player plays, where the web view's Wake
   Lock may not be there.

## Build and run

You need macOS with Xcode (Swift tools 5.9 or newer; use an Xcode version that
[Capacitor 8 supports](https://capacitorjs.com/docs/getting-started/environment-setup)), an iPad
or the simulator, and the usual toolchain from the root README (Node, pnpm, Rust for the engine).
A free Apple ID is enough to run on your own iPad; TestFlight and the App Store need the Apple
Developer Program (P3-02).

```sh
pnpm install
pnpm --filter @opentiles/ios-shell ios    # builds the engine and web app, then runs `cap sync ios`
pnpm --filter @opentiles/ios-shell open   # opens the Xcode project
```

In Xcode, select the **App** target → **Signing & Capabilities** → choose your team, pick your iPad
as the run destination and press **Run**. The first build downloads `capacitor-swift-pm` from
GitHub through Swift Package Manager; after that it builds offline.

Signing in Xcode with a free Apple ID usually fails on the bundle identifier `org.opentiles.app`
(someone else has registered it): change it in the same pane, for example by adding your team ID.
`pnpm device` below does this for you.

- After changing the web app, run `pnpm --filter @opentiles/ios-shell ios` again.
- After changing the plugin's Swift code, just build again in Xcode: the package is referenced by
  path (`ios/App/CapApp-SPM/Package.swift`, rewritten by every `cap sync`).
- **Plugin tests:** open `plugins/core-midi/Package.swift` in Xcode, choose an iPad simulator and
  press ⌘U.

The scripts run `cap telemetry off` first: the Capacitor CLI otherwise sends usage data (including
the app ID) when it runs in an interactive terminal.

### Install it yourself

The user-facing steps are in [docs/ipad-app.md](../../docs/ipad-app.md); the reasons in ADR 0023.

```sh
pnpm --filter @opentiles/ios-shell ipa                     # unsigned build/OpenTiles.ipa
TEAM=ABCDE12345 pnpm --filter @opentiles/ios-shell device  # sign with your team, install on the iPad
```

- **`ipa`** builds the public web app (as deployed: verified catalogue only, no sync server, source
  maps removed), runs `cap sync`, makes a Release build with code signing off and zips
  `Payload/App.app`. AltStore, SideStore and Sideloadly sign it with the user's Apple ID. The app
  has no entitlements, which is what lets a free Apple ID sign it: keep it that way (no App Groups,
  iCloud, push or associated domains) or free signing stops working.
- **`device`** picks the one paired iPad or iPhone (`DEVICE=<name or UDID>` when there are more),
  stops with a hint if Developer Mode is off, builds with `-allowProvisioningUpdates
-allowProvisioningDeviceRegistration` for team `TEAM`, and installs with `xcrun devicectl`. The
  bundle identifier becomes `org.opentiles.app.<TEAM>` (`BUNDLE_SUFFIX` changes the part after
  `org.opentiles.app`) through `OPENTILES_BUNDLE_SUFFIX`, which only the App target reads.
- **Versions:** `CFBundleShortVersionString` is this package's `version` (`apps/web` has the same
  one, and both move together at each release, PLAN.md P3-09), `CFBundleVersion` the
  commit count (`BUILD_NUMBER` overrides it). `SKIP_WEB=1` reuses the web build already synced.
- **CI** (`.github/workflows/ios.yml`, macOS): every pull request and every push to `main` builds
  the IPA and runs the plugin tests on an iPad simulator, because every change to the web app is a
  change to the app. A tag `v<version>` also puts `OpenTiles.ipa` and
  `altstore.json` on a **draft** release; read it, then publish it by hand. AltStore and SideStore
  read the source at `…/releases/latest/download/altstore.json`.

### First-build checklist

How to run each check. Which ones are done is tracked in one place, the
[iPad device checklist](../../PLAN.md#ipad-device-checklist) in PLAN.md.

1. ✓ The app and the plugin compile (2026-10-09), with MIDI out (2026-10-17). ✓ `pnpm ipa` makes
   an unsigned IPA with no entitlements, and the plugin tests pass in CI on an iPad simulator
   (2026-10-22). ✓ `pnpm device` with a free Apple ID installs on an iPad Pro (M1, iPadOS 27).
   Still to try: AltStore, SideStore and Sideloadly.
2. Found on the first device run (2026-10-22) and fixed: the piano samples arrive from
   `capacitor://` with status 0, which the loader took for a failure (the app played the stand-in
   synth); the status bar did not follow the page's dark theme. Keyboard size is not detected (MIDI
   does not report it); choose it under Settings → Keyboard size.
3. The app starts with no network (aeroplane mode) and the catalogue opens. The top bar sits
   below the status bar (`env(safe-area-inset-top)`), in both orientations.
4. A USB MIDI keyboard (USB-C, or the Lightning to USB Camera Adapter) appears after
   **Connect MIDI keyboard** (✓ 2026-10-22); notes advance wait mode; in play-along, notes played
   on the beat are judged on time (compare with the on-screen keys).
5. Unplugging and replugging the keyboard updates the device list and notes resume.
6. A Bluetooth MIDI keyboard paired from Settings → MIDI keyboard appears too.
7. With "Plays on: My keyboard", Listen and the Player play on the keyboard's own sound, on time,
   with its pedal; Stop leaves nothing sounding; unplugging it mid-piece pauses the Player.
8. **Use microphone** shows the permission text from `Info.plist`, and detection works in the
   app's WebView.
9. Sound starts after a tap; check it with the Ring/Silent switch on and off (see follow-ups).
10. Split View at a third of the screen and rotation keep the practice screen usable.
11. An imported piece is still in the library after quitting and reopening the app, and the "Add to
    Home Screen" hint does not appear.
12. Xcode → **Product → Generate Privacy Report** on an archive lists the plugin's manifest.

## App Store notes (P3-02)

- **Free**, no in-app purchases, no ads, no account, no tracking, no notifications (the
  principles in the root README, spec §10). App Privacy answer: **Data Not Collected**.
- **Value beyond the website** (App Review guideline 4.2): native MIDI keyboard support through
  CoreMIDI, which Safari cannot offer on iPad, and the catalogue works fully offline. Say this in the
  review notes, and tell the reviewer the app also works without a keyboard (on-screen keys,
  microphone).
- **Screenshots and previews** use public-domain catalogue pieces only
  ([legal guardrails](../../docs/legal-guardrails.md)).
- **Category:** Music, with Education as the secondary category.
- **Export compliance:** the only encryption is WebKit's Web Crypto (encrypted backups, later sync).
  Confirm the exemption when answering in App Store Connect, then add
  `ITSAppUsesNonExemptEncryption` = `NO` to `Info.plist` so builds skip the question.
- **Licence:** the code is AGPL-3.0-or-later and contributors keep their copyright (DCO). App Store
  terms add usage rules the AGPL does not allow, so get advice before the first release, for
  example on adding an App Store permission under AGPL §7 with contributors' agreement. The
  source stays public and the About page links to it.
- **Versions:** `pnpm ipa` and `pnpm device` set `MARKETING_VERSION` from `package.json` and
  `CURRENT_PROJECT_VERSION` from the commit count; the Xcode project's values are for builds from
  Xcode itself.
- **Icon and launch image** come from `scripts/render-assets.py` (needs Pillow); they replace
  Capacitor's placeholder images.

## Privacy manifest

- The plugin ships `plugins/core-midi/ios/Sources/CoreMidiPlugin/PrivacyInfo.xcprivacy` as a
  package resource: no tracking, no collected data, and the **system boot time** API with reason
  **35F9.1**, because it reads `mach_absolute_time()` to measure the time between a key press and
  its arrival in the WebView (CoreMIDI timestamps use that clock).
- Capacitor's framework ships its own manifest.
- The app target has none: its own Swift code (`AppDelegate`, `SceneDelegate`) uses no
  required-reason API, and the web app's storage (IndexedDB) belongs to WebKit. Add one in Xcode
  (File → New → File → App Privacy) if review asks for it.
- `NSMicrophoneUsageDescription` and `NSBluetoothAlwaysUsageDescription` (needed by Apple's
  Bluetooth MIDI pairing screen; without it iOS ends the app when the screen opens) explain the
  microphone and Bluetooth in British English; add a German `InfoPlist.strings` when the app gets
  German (P2-14).

## Design notes

- **A local plugin package rather than code in the app target.** `cap sync` adds it to the Swift
  package graph and registers its class (`packageClassList`), so nobody hand-edits
  `project.pbxproj`, and its tests run on their own. The CLI finds the class by the first named
  `@objc` attribute in each Swift file, so only `CoreMidiPlugin.swift` may have one.
- **MIDI 1.0 Universal MIDI Packets** (`MIDIInputPortCreateWithProtocol`, iOS 14+): the current,
  non-deprecated API. CoreMIDI resolves running status, real-time bytes and SysEx, which keeps the
  Swift parser to a few lines.
- **Threading.** CoreMIDI posts setup notifications to the run loop of the thread that created the
  client, so the session lives on the main thread. The receive block runs on CoreMIDI's thread and
  touches only its arguments; events are posted to JavaScript from the bridge's queue, where
  Capacitor also adds and removes listeners.
- **One `NativeMidiInput` at a time.** Native `start()` and `stop()` are global; the practice screen
  only ever has one MIDI input.
- **Never resolve a promise with the plugin object.** Capacitor's plugin is a Proxy that answers
  `then`, so the web app passes the module namespace around instead.
